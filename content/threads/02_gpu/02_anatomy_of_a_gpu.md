### داخل GPU چه خبره؟

توی تِرِد قبلی فهمیدیم که یکی از دلایل اصلی استفاده از GPU اینه که خیلی از محاسبات Graphics قابلیت **پردازش موازی** دارن.

اما حالا یه سؤال مهم‌تر داریم:

> **این محاسبات موازی دقیقاً کجای GPU انجام می‌شن؟**

اصلاً وقتی یه برنامه به GPU می‌گه:

> "این مدل سه‌بعدی رو بگیر و Render کن."

چه اتفاقی داخل GPU می‌افته؟

<br />

برای جواب دادن به این سؤال، اول باید یه تصویر کلی از فرآیند هایی که داخل GPU وجود دارن، داشته باشیم.

<br />

ما سه بخش اصلی داریم که به عنوان برنامه نویس گرافیک نیاز داریم باهاشون آشنا بشیم:

1. {{< readmore type="" title="Command Processing | پردازش فرمان ها" open="false" >}}

اول از همه، GPU باید بدونه **چه کاری باید انجام بده.**

برنامه‌ی ما یک سری دستور و دیتا به GPU می‌فرسته و GPU اون‌ها رو برای اجرا آماده می‌کنه.

مثلاً:

* این Vertex رو پردازش کن.
* این Triangle رو Render کن.
* از این Shader استفاده کن.

{{< /readmore >}}

2. {{< readmore type="" title="GPU Memory | حافظه جی پی یو" open="false" >}}

GPU برای انجام محاسباتش به داده نیاز داره.
ورتکس ها، تکستچر ها، بافر ها و اطلاعات مختلف دیگه باید جایی قرار داشته باشن که GPU بتونه بهشون دسترسی پیدا کنه.

اینجاست که **GPU Memory** وارد ماجرا می‌شه.

بعداً یک تِرِد کامل رو به حافظه و انتقال داده بین CPU و GPU اختصاص می‌دیم.

{{< /readmore >}}

3. {{< readmore type="" title="Compute Units | واحد های محاسباتی" open="false" >}}

خب، بالاخره محاسبات کجا انجام می‌شن؟

GPU منابع محاسباتی زیادی داره که می‌تونن تعداد زیادی عملیات رو به‌صورت موازی اجرا کنن.

به‌صورت کلی می‌تونیم این منابع رو **Compute Units** در نظر بگیریم.

البته اسم و ساختار دقیق این واحدها بین معماری‌های مختلف فرق می‌کنه، ولی فعلاً همین رو بدونیم که:

> **بخش بزرگی از قدرت پردازشی GPU از همین پردازش موازی میاد.**

{{< /readmore >}}

#### حالا می‌رسیم به بخش مهم‌تر داستان.

وقتی می‌گیم:

> "این مدل سه‌بعدی رو Render کن."

داده‌ی ما یک‌دفعه تبدیل به تصویر نمی‌شه.



از چند مرحله عبور می‌کنه. که هرکدوم یه فرآیندی رو اجرا میکنن.
مثل خط تولید کارخونه...

به این مسیر می‌گیم: **Graphics Pipeline**

<br />

در ساده‌ترین حالت می‌تونیم سه مرحله‌ی مهمش رو این‌طور در نظر بگیریم:


1. {{< readmore type="" title="Vertex Processing | پردازش رأس‌ها" open="false" >}}

اینجا رأس(Vertex) های اشکال ما پردازش می‌شن و موقعیتشون برای مراحل بعدی آماده می‌شه.

{{< /readmore >}}

2. {{< readmore type="" title="Rasterization | رسترایزیشن" open="false" >}}

اینجا اشکال(Geometry) ما به قطعه(Fragment) هایی تبدیل میشن که مشخص می‌کنن کدوم قسمت‌های صفحه تحت تأثیر شکل ما قرار گرفتن. تا پیکسل های مربوطه شکل بگیرن.

<br />

به صورت خلاصه، مرحله رسترایزیشن اشکال مارو تبدیل به قطعه ها و فرگمنت هایی میکنه که بعدا تبدیل بشن به پیکسل توی صفحه.

{{< /readmore >}}


3. {{< readmore type="" title="Fragment / Pixel Processing | پردازش فرگمنت‌ها / پیکسل‌ها" open="false" >}}

حالا که فرگمنت(Fragment) ها مشخص شدن...
در این مرحله مشخص می‌کنیم قطعه(Fragment) ها در نهایت چه نتیجه‌ای در تصویر داشته باشن؛ مثلاً چه رنگی داشته باشن، چه Texture ای روی اون‌ها اعمال بشه و نور چطور روی اون‌ها تأثیر بذاره.

{{< /readmore >}}
